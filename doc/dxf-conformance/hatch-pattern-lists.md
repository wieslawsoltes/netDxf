# HATCH pattern-list grammar and count validation

Baseline: merged PR #44, commit `98ed11ef41c4bfe181b3db77f916d4c1477b6338`, production tree `ca9b48a22380d461a76d08e6ea63426d0648ea63`.

The old pattern-line reader consumed values positionally without checking their group codes. It silently accepted some negative counts, substituted the values of unrelated real-valued groups for geometry, ignored surplus lines/dashes, and failed on comments or reordered scalar fields. Catching an arbitrary conversion exception was not a sufficient grammar check.

## Implemented contract

Group 78 declares a nonnegative number of group-53 pattern lines. Each line contains exactly one scalar field 43, 44, 45, 46 and one group-79 nonnegative dash count. The counted dash packet contains exactly that many group-49 lengths. Scalar order within a group-53 line is independent; the dash packet remains consecutive apart from text comments. Zero lines and zero-length dash lists are supported. Positive, negative and zero dash lengths retain their existing meanings and order.

Counts limit parsing but are not used as allocation capacities. Collections grow only after consuming valid fields. Negative counts, duplicates, wrong/missing required fields and orphan/overflow pattern fields are rejected with HATCH, group-code and position context. Comments (group 999) are ignored in the text grammar, including inside dash packets. This change does not admit comments to binary DXF.

Physical EOF is still handled by the strict transport codec. The public `DxfDocument.Load` convention remains unchanged: Debug propagates contextual exceptions; Release returns null for parser failure. Caller-owned streams remain open. Production target frameworks, signing and public APIs are unchanged.

The conversion between DXF global pattern data and PAT-local public line definitions is retained. Clone and alternating text/binary output preserve pattern lines, ordered dash values, seeds, boundary count, elevation, following XData and the following independent LINE entity.

## Executed regression evidence

450 additional registered independent-byte cases exercise canonical and reordered lines, text comments, empty lists, 23 malformed variants and ten physical truncation positions per applicable version/transport combination. Fixtures are encoded with the independent test fixture encoder, not generated by the production writer under test.

With these identical tests and unchanged PR44 production: **6,752 passed / 294 failed in Debug**, **6,896 passed / 150 failed in Release**. With the correction: **7,046 passed / 0 failed in both configurations**, using the signed production assembly compiled by the .NET 8 compiler and executed on .NET 8. The differing failure totals also reflect Debug diagnostic assertions rather than a claim that every Debug failure was previously accepted.

The independent ezdxf 1.4.4 verifier reads all twelve retained output files (24 HATCH entities, 48 pattern lines), compares exact binary64 geometry/dash values and surrounding metadata, and reports **zero audit errors and zero repairs**. Run:

```sh
python tools/verify_hatch_pattern_lists.py artifacts/conformance
```

The 15 Python ledger tests and generated coverage check remain separate. Final-head Linux/Windows Debug/Release, netstandard2.0 and source-audit CI are merge gates, not inferred from these local runs.

## References and remaining scope

Autodesk defines the group-78 repetition and links the Pattern Data grammar from its HATCH reference: https://help.autodesk.com/cloudhelp/2023/ENU/AutoCAD-DXF/files/GUID-C6C71CED-CE0F-4184-82A5-07AD6241F15B.htm

The keyed scalar and counted-list behavior above is the explicit supported typed grammar; it is not a general recovery parser for arbitrary malformed CAD files. Reordering across a group-53 line boundary or across the group-79 counted packet is not inferred.

Not implemented here: complete counted boundary-path validation; global pattern angle/scale fields arriving after the line-definition packet; arbitrary-affine HATCH transformation fidelity; strict general XData schemas; PAT-file persistence of drawing-only fields; native AutoCAD execution. Unknown raw preservation remains separate. HATCH as a whole remains partial, and this correction does not add any missing entity family or establish full DXF conformance.
