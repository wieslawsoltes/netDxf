# Observable collection insertion and HATCH source retention

`ObservableCollection<T>.Insert` now inserts an item without firing removal callbacks for the existing item at that index. Valid indices are zero through `Count`, inclusive, including insertion into an empty collection. The existing collection order is preserved around the inserted item. `BeforeAddItem` runs before mutation, followed by insertion and `AddItem`. A canceled or throwing `BeforeAddItem` leaves the sequence unchanged; the existing cancellation exception contract remains in place. Ordinary removal behavior is unchanged. Exceptions thrown by after-add application callbacks occur after insertion and are outside a rollback promise.

The previous implementation fired both removal callbacks for the indexed member but never removed it from the internal list. HATCH path insertion consequently kept an old path while releasing its source reactor occurrences and invoking source-removal logic. It also rejected insertion at `Count`. This correction does not change any DXF geometry schema; it preserves the source graph while adding a path.

Thirteen focused generic cases check front/middle/end and empty insertion, invalid indices, cancellation, throwing pre-add callbacks, event order, and unchanged ordinary removal events. Thirty-six additional cases insert an explicitly authored closed rectangle into pinned independently produced HATCH drawings across all six supported profiles and both transports. The existing source fixtures are producer evidence, and the added rectangle is declared geometry; no native application execution or rendering is claimed.

Those HATCH cases preserve actual original path identity, geometry packets, source order/counts, source entity membership, managed reactor occurrence sequences and persistent backlinks. Each insertion adds exactly one path and its source without a removal callback. Output observations retain actual callback counts and managed occurrences before export, because a reload alone can rebuild the managed occurrence list and conceal an earlier insertion defect. A separate packet verifier checks the 36 exported drawings, the emitted observations, profile and transport, unchanged original source geometry, and four effective corruption controls. Three controls mutate actual ASCII DXF source references, source geometry and the inserted source owner; both wire readers accept those modified packets before semantic validation rejects them. The fourth corrupts an emitted reactor observation. It normalizes the pre-existing permitted omission of zero-valued optional LWPOLYLINE width/bulge fields while comparing original HATCH boundary packets exactly.

Debug and Release each pass all 49 cases and the 36-output independent gate, with zero ezdxf audit errors or repairs. The identical final test binary against the frozen preceding DLL passes three cases and fails 46; the final DLL passes all 49. The [qualification receipt](receipts/observable-insert/qualification.json) pins source, DLL/test hashes, actual before/after results, producer manifest, output observations and all target builds. The original before-output packets are retained in a deterministic compressed archive beside the receipt.

Source production commit is `daa5309`; the frozen test/source checkpoint is `74798f5`. All five Release targets and Debug net8.0/netstandard2.0 build with zero errors and the existing 561 CS1591 warnings per target, with no additional warning categories. Whole-repository integration and CI qualification remain separate from this focused correction.
