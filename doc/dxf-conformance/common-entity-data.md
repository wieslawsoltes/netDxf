# Common graphical entity data

`EntityObject`, `AttributeDefinition` and `Attribute` preserve optional color names, shadow modes and opaque proxy graphics in their `AcDbEntity` subclass. This covers model space, paper space, block definitions and inserted attributes. Existing color, transparency and typed geometry APIs keep their existing meaning.

| Public property | DXF field | Admitted output profiles | Absence |
| --- | --- | --- | --- |
| `ColorName` | 430 | 2004, 2007, 2010, 2013, 2018 | `null`; an empty string remains present |
| `ShadowMode` | 284 | 2007, 2010, 2013, 2018 | Nullable `EntityShadowMode`; explicit zero remains present |
| `ProxyGraphics` | 92 + 310 before 2013; 160 + 310 from 2013 | All six supported profiles | `null`; an empty array writes an explicit zero count |

The [Autodesk common entity reference](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-DXF/files/GUID-3610039E-27D1-4E23-B6D3-7E60B22BB5BD.htm) defines these common fields and the four shadow values. It also records that shadow mode remains available for compatibility although newer products no longer use it. [ezdxf's graphical entity reference](https://ezdxf.readthedocs.io/en/stable/dxfentities/dxfgfx.html) establishes the 2004 color-name and 2007 shadow-mode gates. The version-pinned [ezdxf 1.4.4 implementation](https://github.com/mozman/ezdxf/blob/v1.4.4/src/ezdxf/entities/dxfgfx.py) selects proxy byte-count group 92 through 2010 and group 160 from 2013. The Autodesk common table lists the older group 92; the reader also accepts that form in modern files and normalizes it on output. The reader additionally accepts group 160 from R2010: the pinned native AC1024 corpus below contains this field. Canonical output remains group 92 through R2010 and group 160 from R2013. R2000, R2004 and R2007 inputs with group 160 remain rejected.

Proxy graphics are stored data, not a second geometry engine. The library does not decode, execute or regenerate the payload. `Clone`, reversal and geometric transforms preserve its bytes. After editing typed geometry, callers should clear the cache with `ClearProxyGraphics()` or assign regenerated bytes if the consuming application uses it. This contract does not claim rendering equivalence after geometry changes. Color names likewise remain stored names; assigning one does not resolve a color book or change `Color`.

The API makes defensive copies on assignment, retrieval and cloning. Each payload is limited to `MaximumProxyGraphicsBytes` (16 MiB). Reading allocates storage from received bytes; it never reserves memory from an advertised count. Counts must be nonnegative, unique and exact. Chunks retain their order, while the byte-count field may appear before or after them. An absent count with chunks, an excessive count, excessive actual bytes, oversized chunks, incomplete packets and duplicate color/shadow fields are rejected. Input accepts chunks up to 128 bytes; output writes at most 127 bytes per chunk, following the independent producer's convention.

The reader checks that the first graphical subclass is `AcDbEntity` in both Debug and Release and ends the common packet at the next subclass. HATCH boundary group 92 and OLE native group 310 therefore remain separate. Unsupported color/shadow downgrades are rejected before output, including metadata held by block attribute definitions and inserted attributes. Literal backslashes and framing controls in color-name strings use DXF Unicode escapes, preserving repeated roundtrips and Unicode names in both transports.

`CommonEntityDataTests` adds 372 cases across six profiles and both transports, packet sizes around chunk boundaries, presence, malformed input, bounded allocation, ordinary entity clones and the Spline/Helix copy path, attributes, independent inputs, cache semantics and output preflight. Fixtures from `tests/fixtures/common-entity-data/generate.py` use ezdxf 1.4.4 and contain a valid proxy polyline command. Their manifest records producer and SHA256 hashes. The independent verifier now requires all 110 emitted drawings, checks the original common-subclass tags, decodes the 36 preserved producer commands, checks unrelated payloads and requires zero ezdxf audit errors or repairs:

```sh
python tools/verify_common_entity_data.py artifacts/conformance
```

Qualification on the module branch completed with 20,320 passed and zero failed tests in each of Debug and Release (19,948 existing tests plus 372 new cases). The independent 108-drawing verifier passed for both configurations; negative checks reject a missing profile or altered proxy bytes. An API-compatible comparison against the pre-module library lost all three caches in each of the twelve producer inputs; the implementation preserved all three in all twelve.

The low-level tag checks are deliberate: ezdxf 1.4.4's optimized LINE loader does not populate its proxy cache property. The fixture generator also documents an ezdxf binary-export issue and uses its independent typed tag compiler and binary writer to encode the ASCII producer output. No netDxf code produces those input files.

Material, plot-style and visual-style object references, and optional common data on internal VERTEX records, remain outside this module. They require separate ownership and representation work. Byte preservation here does not extend the library's supported entity-type inventory.

## Native R2010 proxy count compatibility

`CommonProxy160Tests` adds 146 cases for literal group 160 input across all six profiles and both transports. It checks empty packets and chunk boundaries, counts before and after chunks, 64-bit negative and excessive values, duplicate 92/160 counts, incomplete payloads, bounded allocation, independent OLE payload framing, following XData, clone isolation and canonical output.

The shared corpus `tests/fixtures/table-oracle/sample_AC1024_ascii.dxf.gz` is the unmodified AC1024 sample pinned to [ACadSharp f6a7f1e7e502c6fe9d1e840e576b6124ec0ded11](https://github.com/DomCR/ACadSharp/blob/f6a7f1e7e502c6fe9d1e840e576b6124ec0ded11/samples/sample_AC1024_ascii.dxf). Its decompressed SHA256 is `c97e857047ad4cecd84754ea1a8638e47508e339fd489f1e895ee7332127b372`. It contains 22 common proxy caches totaling 45,416 bytes, spanning MESH, WIPEOUT, ACAD_TABLE, MULTILEADER, IMAGE and PDFUNDERLAY source records.

The conformance test copies only each original common count/chunk packet into a LINE carrier and records its original file, entity type, handle and cache SHA256 as XData. The mandatory independent verifier reads the original compressed corpus itself, verifies the pinned source hash, requires a bijective mapping to all 22 caches in each transport, compares every emitted byte, and requires canonical R2010 group 92 output and zero ezdxf audit errors or repairs. These two carrier drawings qualify the stored common packets. They do not establish full-file native interoperability, support for the original entity bodies, or proxy rendering equivalence. The full source drawing still encounters the separately documented live ACIS history boundary.

The recovery module passes 22,791 tests with zero failures in each of Debug and Release, including all 518 common-metadata cases. The 110-drawing verifier passes in both configurations. Four deliberate corruption controls reject changed native payload bytes, an invalid source mapping, noncanonical R2010 group 160 output and a missing native output drawing. A separately authored 156-case old/new reader probe passes all 156 cases with the fix; the published baseline fails exactly the six valid R2010 group 160 cases covering empty, nonempty and reordered counts in both transports. All five Release targets and netstandard2.0 Debug compile successfully, with the existing XML documentation warnings.
