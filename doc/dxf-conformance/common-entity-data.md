# Common graphical entity data

`EntityObject`, `AttributeDefinition` and `Attribute` preserve optional color names, shadow modes and opaque proxy graphics in their `AcDbEntity` subclass. This covers model space, paper space, block definitions and inserted attributes. Existing color, transparency and typed geometry APIs keep their existing meaning.

| Public property | DXF field | Admitted output profiles | Absence |
| --- | --- | --- | --- |
| `ColorName` | 430 | 2004, 2007, 2010, 2013, 2018 | `null`; an empty string remains present |
| `ShadowMode` | 284 | 2007, 2010, 2013, 2018 | Nullable `EntityShadowMode`; explicit zero remains present |
| `ProxyGraphics` | 92 + 310 before 2013; 160 + 310 from 2013 | All six supported profiles | `null`; an empty array writes an explicit zero count |

The [Autodesk common entity reference](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-DXF/files/GUID-3610039E-27D1-4E23-B6D3-7E60B22BB5BD.htm) defines these common fields and the four shadow values. It also records that shadow mode remains available for compatibility although newer products no longer use it. [ezdxf's graphical entity reference](https://ezdxf.readthedocs.io/en/stable/dxfentities/dxfgfx.html) establishes the 2004 color-name and 2007 shadow-mode gates. The version-pinned [ezdxf 1.4.4 implementation](https://github.com/mozman/ezdxf/blob/v1.4.4/src/ezdxf/entities/dxfgfx.py) selects proxy byte-count group 92 through 2010 and group 160 from 2013. The Autodesk common table lists the older group 92; the reader also accepts that form in modern files and normalizes it on output.

Proxy graphics are stored data, not a second geometry engine. The library does not decode, execute or regenerate the payload. `Clone`, reversal and geometric transforms preserve its bytes. After editing typed geometry, callers should clear the cache with `ClearProxyGraphics()` or assign regenerated bytes if the consuming application uses it. This contract does not claim rendering equivalence after geometry changes. Color names likewise remain stored names; assigning one does not resolve a color book or change `Color`.

The API makes defensive copies on assignment, retrieval and cloning. Each payload is limited to `MaximumProxyGraphicsBytes` (16 MiB). Reading allocates storage from received bytes; it never reserves memory from an advertised count. Counts must be nonnegative, unique and exact. Chunks retain their order, while the byte-count field may appear before or after them. An absent count with chunks, an excessive count, excessive actual bytes, oversized chunks, incomplete packets and duplicate color/shadow fields are rejected. Input accepts chunks up to 128 bytes; output writes at most 127 bytes per chunk, following the independent producer's convention.

The reader checks that the first graphical subclass is `AcDbEntity` in both Debug and Release and ends the common packet at the next subclass. HATCH boundary group 92 and OLE native group 310 therefore remain separate. Unsupported color/shadow downgrades are rejected before output, including metadata held by block attribute definitions and inserted attributes. Literal backslashes and framing controls in color-name strings use DXF Unicode escapes, preserving repeated roundtrips and Unicode names in both transports.

`CommonEntityDataTests` adds 372 cases across six profiles and both transports, packet sizes around chunk boundaries, presence, malformed input, bounded allocation, ordinary entity clones and the Spline/Helix copy path, attributes, independent inputs, cache semantics and output preflight. Fixtures from `tests/fixtures/common-entity-data/generate.py` use ezdxf 1.4.4 and contain a valid proxy polyline command. Their manifest records producer and SHA256 hashes. The independent verifier requires all 108 emitted drawings, checks the original common-subclass tags, decodes the 36 preserved producer commands, checks unrelated payloads and requires zero ezdxf audit errors or repairs:

```sh
python tools/verify_common_entity_data.py artifacts/conformance
```

Qualification on the module branch completed with 20,320 passed and zero failed tests in each of Debug and Release (19,948 existing tests plus 372 new cases). The independent 108-drawing verifier passed for both configurations; negative checks reject a missing profile or altered proxy bytes. An API-compatible comparison against the pre-module library lost all three caches in each of the twelve producer inputs; the implementation preserved all three in all twelve.

The low-level tag checks are deliberate: ezdxf 1.4.4's optimized LINE loader does not populate its proxy cache property. The fixture generator also documents an ezdxf binary-export issue and uses its independent typed tag compiler and binary writer to encode the ASCII producer output. No netDxf code produces those input files.

Material, plot-style and visual-style object references, and optional common data on internal VERTEX records, remain outside this module. They require separate ownership and representation work. Byte preservation here does not extend the library's supported entity-type inventory.
