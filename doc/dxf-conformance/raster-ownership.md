# RASTERVARIABLES dictionary ownership

Baseline: `2ea8929681eb81e2eece8190851985494522da62`, after merged PR #19.

## Defect and correction

The writer added ACAD_IMAGE_VARS directly to the named object dictionary but wrote the RASTERVARIABLES object's owner handle (group 330 outside application/reactor groups) as the ACAD_IMAGE_DICT handle. The parent and child therefore disagreed. This affected empty drawings as well as drawings containing images; self-round-trip tests had not detected it because the reader did not validate that ownership edge.

Pass the named object dictionary handle to WriteRasterVariables. IMAGEDEF objects continue to belong to ACAD_IMAGE_DICT; no image-definition, reactor, class, raster-value or XData policy is changed. This fixes one serialized ownership edge, not general unknown-object preservation or graph validation.

## Version and regression coverage

All six admitted DXF families (AC1015, AC1018, AC1021, AC1024, AC1027, AC1032), text and binary. The 36 registered cases cover empty drawings, direct images and shared image definitions referenced by both a nested INSERT and a direct image. Each case exercises all nine image-unit values and three alternating-transport save/load cycles, checking display flags, quality, metadata, object/dictionary handles and independent IMAGEDEF ownership. The parser distinguishes object-owner group 330 from reactor/application group 330.

New tests against the old writer: **2,663 passed / 36 failed**. Corrected signed production library: **2,699 passed / 0 failed**, Debug and Release. Cross-platform SDK, netstandard2.0 and source-audit CI remain additional merge gates.

## Independent interoperability evidence

The bug was discovered while verifying MTEXT background fixtures with ezdxf 1.4.4. The expanded independent corpus contains 36 raster fixtures generated by the tests: before the fix, ezdxf reported **36 ownership repairs across 36 files**; afterward, **0 errors and 0 repairs across all 36 files**. The verifier checks ownership before calling audit, so repair cannot conceal failure. It never writes the drawings or loads external image files.

```sh
dotnet run --project tests/netDxf.Conformance -c Release
python -m pip install ezdxf==1.4.4
python tools/verify_raster_ownership.py artifacts/conformance --output artifacts/raster-independent.json
```

The Python dependency is development-only and does not enter netDxf. This evidence establishes agreement with one independent implementation for these fixtures. It is not an AutoCAD execution or full-standard certificate.
