# Stored HATCH affine boundary transforms

The later [explicit pattern affine module](hatch-pattern-affine.md) adds validated affine line-family packets for non-doubled predefined/custom fills, subject to its separate stored WCS Point2d Origin contract. Earlier statements below that reject all non-similar patterns describe this module’s original boundary.

This is the qualification record for the line/spline affine module. Its former conic and bulged-polyline restrictions are superseded by [Affine HATCH conic boundaries](hatch-conic-affine.md); the original observations below remain historical evidence.

`Hatch.TransformBy` now transforms stored LINE and SPLINE boundary coordinates directly. It also transforms closed POLYLINE paths whose bulges are all zero. The image plane comes from the cross product of the two transformed object-coordinate axes, rather than treating the extrusion normal as a position vector. This preserves world-space geometry under nonuniform scaling, shear, rotations and reflections, including a tilted original plane.

The former conversion through `Entities.Spline` changed a stored non-rational flag to rational even for an identity matrix, and rejected stored periodic knot forms accepted by the HATCH reader. The old normal transformation also projected tilted-plane geometry into the wrong plane under nonuniform scaling and shear. An independent 32-case harness observed 28 failures on the merged baseline, including geometry errors up to 6.97 world units. The final independent harness adds eight rank-two matrix cases. The same 40-case harness passes 4 cases on the baseline and all 40 on the final source; maximum world-space error falls from 8.4552 to below 6.60e-15. Exact source, results and DLL hashes are recorded in the [qualification receipt](receipts/hatch-affine/qualification.json). The earlier 32-case observation is historical, not an additional set of final cases.

Spline degree, rational and periodic flags, knot values and order, control count and stored weights are preserved. Control positions and fit points transform as positions; optional tangents transform as vectors, without translation or normalization. Negative and nonunit stored weights remain data even when the rational flag is zero. This is storage-preserving affine algebra, with no spline evaluation, fitting, periodic closure inference or knot regeneration. A spline in a mixed boundary using the existing conic similarity path also avoids conversion through `Entities.Spline`.

Path classifications, straight-polyline closure, pixel size and unrelated entity metadata survive. Seeds transform in the same plane as boundary positions. For an exact identity matrix and zero translation, direct boundary objects and stored values remain unchanged. Temporary copies do not call an overridable edge `Clone` or `ConvertTo` method. Normal orientation follows the former transformed-normal direction when it has a component perpendicular to the resulting plane; its orthogonality to the new plane is always established geometrically.

Transforms validate finite input, the two-dimensional image plane and prospective stored geometry before unlinking source references or changing the HATCH. Rejected input preserves path/edge object identity, associativity, source occurrences and reactors, registered membership, handle allocation, pattern state and path callbacks. After a successful transform, the established API behavior unlinks an associative HATCH while retaining its former source entities, their identities and geometry. This is not automatic associative geometry regeneration. Exceptions thrown by application event handlers during a successful mutation are outside the validation guarantee.

General affine changes cannot be represented by the existing single angle/scale controls for hatch patterns and gradients. Non-similarity transforms of those fills now throw `NotSupportedException` before mutation. Non-similarity changes to circular/elliptic boundary representations and bulged polylines are likewise declined rather than approximated by this module. Existing similarity conversion of those curves remains supported where the transformed entity normal agrees with the actual image plane. Similarity uses orthogonal transformed plane axes of equal length, compared at a relative tolerance of 1e-12. Pattern origin/line regeneration and general gradient rendering are separate work.

Two older INSERT tests used nonuniform transforms on patterned HATCHes while asserting only seed or fit-point positions. Their geometry fixtures now explicitly use solid fills; separate tests assert conservative patterned/gradient rejection. This narrows those former geometry-only observations and does not present them as exact transformed-pattern qualification.

The positive output corpus derives from twelve pinned ezdxf 1.4.4 producer drawings already recorded under `tests/fixtures/hatch-spline-relations`. Five matrices (identity, rotation, nonuniform scale, three-dimensional shear and reflection), two original planes, six DXF versions and both input/output transports produce 120 required drawings. Each contains four spline packets and a following closing LINE, plus independent following modelspace geometry. The tests explicitly change the first stored weight to -2.5 on non-rational packets, set the original plane and elevation, apply the transform, and perform three alternating-transport save/reload cycles. These are declared transformations of independent producer packets, not untouched native CAD examples.

Twenty additional required R2018 outputs cover closed straight polylines under the same five matrices, two planes and both output transports. The independent Python verifier reconstructs world coordinates with ezdxf's OCS implementation and NumPy matrix multiplication, compares every control, fit, optional tangent, closing edge, seed and polyline vertex, checks stored spline fields and following geometry, and audits each complete output without repairs. It requires all 140 files. Actual ASCII output corruption controls change rationality, periodicity, a weight, a knot, a normal and a control coordinate; each must be rejected.

The [Autodesk boundary-path schema](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-DC5215D6-E73F-4DFF-8BE9-01CA9610FAEE.htm) distinguishes positions in OCS, vectors, weights and stored flags. The normal derivation follows the orthogonality condition explained in [Physically Based Rendering: Applying Transformations](https://pbr-book.org/4ed/Geometry_and_Transformations/Applying_Transformations): transformed normals must remain perpendicular to transformed surface tangents. Taking the cross product of transformed plane axes gives that direction directly, without requiring an inverse for the full three-dimensional matrix. Rank-two transforms are acceptable when they retain a two-dimensional HATCH plane; collapsed planes and nonfinite or unrepresentable results reject.

No native AutoCAD open/AUDIT/save/reopen, pattern rendering, curve evaluation or full HATCH affine parity is claimed.

Final Debug and Release qualification each passed **8,838 unique cases**, with identical result hashes: 163 new transform cases and 8,675 adjacent HATCH cases. Each configuration passed all 21 independent HATCH gates, including the 140-output affine gate and its six actual-output corruption controls. All five Release library targets (netstandard2.0, net471, net48, net6.0 and net8.0), plus Debug netstandard2.0, compiled with zero errors and the same 561 existing documentation warnings per target. Production source, test source, gate, library, result, build-log and required-output hashes are pinned in the qualification receipt.
