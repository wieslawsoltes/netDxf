# Immutable stored DIMASSOC

Qualified loaded `DIMASSOC` objects are exposed as `DxfStoredDimAssoc` through
`document.Objects.Items`. This API preserves stored association data and exact
registered dependencies. It does not evaluate snapping, update a dimension,
regenerate display blocks or open external drawings.

```csharp
foreach (DxfStoredDimAssoc association in document.Objects.Items.OfType<DxfStoredDimAssoc>())
{
    Dimension dimension = association.Dimension;
    foreach (DxfStoredDimAssocPoint point in association.PointReferences)
    {
        EntityObject geometry = point.Geometry;
        Vector3 storedPoint = point.Point;
        int pointIndex = point.PointIndex;
    }
}
```

The source document and DXF profile remain fixed. There is no public authoring
constructor or editable point list. `Tags` retains the complete immutable
qualified subclass packet; the public projections expose the association mask,
trans-space flag, rotated type and ordered point references. A point includes its
mask-selected index, stored osnap and subentity values, graphics marker, finite
parameter and WCS point. Native finite coordinates such as `2e50` are retained
without interpreting them as evaluated geometry or replacing them with zero.
Noncanonical hexadecimal pointers resolve to the exact physical source objects.
The shared typed transport canonicalizes handle spelling before parsing; use
`DxfRawDocument` when lexical hexadecimal spelling must remain unchanged.

The qualified variant contains one `AcDbDimAssoc` subclass, low-four-bit mask and
up to four ordered `AcDbOsnapPointRef` bundles, each with one main geometry handle,
observed osnap value 1, 3 or 13 and last-point flag zero. Missing or duplicate
public fields, inconsistent mask/bundle counts, invalid public scalar ranges,
null or missing identities and wrong target kinds reject. A reference to a
discarded source VERTEX cannot bind to a generated replacement object.

Repeated main-object paths, intersection handles, external-reference strings,
last-point extensions, other osnap variants, private point classes and private
headers/subclasses retain the whole object as `DxfOpaqueObject`. This decision is
made before queuing any semantic reference bindings. Unknown external paths are
inert stored strings. Opaque preservation qualifies the packet, not a hidden
application dependency graph or a complete native association variant.

Each typed association retains its actual DIMENSION (including ARC_DIMENSION)
extension dictionary, the `ACAD_DIMASSOC` hard-owner entry and persistent-reactor
backlink state. Validation rejects changed ownership, detached dependencies,
changed association reactors or changed backlink presence. It does not invent
missing backlinks or add, drop or update them during save. Common XData remains
available through the ordinary API, including canonical APPID rename tracking
and independent binary storage. Geometry entities remain ordinarily editable;
such edits do not update the stored association values.

Generic `CloneObject` rejects the association and every owned graph containing
it before registration. `EraseOwnedTree` and section-owned erasure reject a
closure containing one before mutation. Ordinary entity and containing-block
removal guard both exposed dimension/geometry dependencies and the association's
owner chain. Opaque DIMASSOC records retain the same owner-chain guard and
conservative guards for their exposed standard handle fields; hidden private
dependencies remain unqualified. These boundaries avoid advertising a partial dimension
clone or erasure operation without a coherent association lifecycle.

The [evidence assessment](dimassoc-assessment.md) pins the primary schema and
independent native inventory. Native records exist in all six AC1015–AC1032
profiles, including AC1015 despite one independent parser's R2004 minimum.
Source-version output is qualified; version conversion is rejected.

The fixture suite pins six unchanged LibreDWG corpus originals at commit
`34f02f54b9aacb5708c1d3d2070efb3e4b2d8c43`, including decoded SHA-256, gzip SHA-256
and Git blob identity. Each scoped extraction retains 32 selected native
association, owner-dictionary, dimension and source-geometry packets exactly
modulo an explicit handle map. Named layer/style resources and empty dimension
display blocks are generated carrier data. They do not qualify the original
display-block geometry or whole-drawing interoperability. Source DIMASSOC and
ownership packets are never regenerated by netDxf to create this evidence.

Each profile has seven typed associations and one real opaque POLYLINE→VERTEX
path. The existing typed POLYLINE reader collapses VERTEX records into values;
the opaque association's stored handle path remains exact, but its separate
VERTEX target identity is not qualified through typed save. Use `DxfRawDocument`
for complete packet/identity preservation of that drawing. Complete original
TS1 imports separately encounter unsupported OLE2FRAME or modern ACIS features.

The mandatory `tools/verify_dimassoc.py` requires 46 outputs, six pinned source
originals and extractions, 192 exactly mapped native packets, exact association
payload/ownership/backlink/XData/opaque retention and zero independent audit
errors or repairs. Five actual output corruptions must be rejected. Audit here
is an ezdxf structural check, not execution in AutoCAD or association evaluation.
