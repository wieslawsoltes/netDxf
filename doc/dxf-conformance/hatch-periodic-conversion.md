# Periodic HATCH boundary conversion and evaluation

Periodic HATCH edges now convert between the expanded DXF control list and netDxf's compact standalone `Spline` representation without regenerating knots, rotating the control polygon, or fitting a new curve. `CreateBoundary` prepares every converted entity and its world coordinates before changing association state or source relationships. Unsupported conversion therefore leaves the original HATCH, paths, edge arrays, source occurrences/reactors, handles and document membership unchanged. Exceptions thrown by application callbacks during a successful commit remain outside this prevalidation guarantee.

The [Autodesk HATCH boundary schema](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-DC5215D6-E73F-4DFF-8BE9-01CA9610FAEE.htm) defines degree 94, rational/periodic flags 73/74, knot/control counts 95/96, knots 40, OCS controls 10/20 and optional weights 42. The [standalone SPLINE schema](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-E1F884F8-AA90-4864-A215-3182D47A9C74.htm) separately defines its flags and WCS controls. These field descriptions do not establish a single compact periodic representation for every native API. This module pins actual expanded producer packets and the existing standalone writer convention separately.

Let degree be `p`, expanded control count be `M`, compact count be `N=M-p`, and knot count be `K`. A supported expanded packet has `K=M+p+1`, `M>=2p+1`, and exactly repeated first/last `p` controls and weights. The overlap comparison uses binary64 bits, including any signed-zero coordinate bits. The adapter removes the first `p` controls/weights into a new entity. The standalone writer prepends the last `p` compact controls/weights, restoring the original expanded sequence exactly. `ConvertFrom` uses that same expansion when creating a new HATCH edge. Every knot and authored fit point/tangent retains its stored value before the established OCS/WCS mapping; no refitting is performed.

The legacy netDxf compact HATCH compatibility form has `K=N+2p+1` and is admitted separately, without removing another prefix. Both forms must satisfy the same qualified periodic curve contract after identifying their compact representation: degree 1–10; at least `p+1` compact controls; finite controls/weights/knots; positive weights; strictly increasing knots; and a finite positive active domain `[U[p], U[N+p]]`. Each of the `2p` exterior span comparisons must satisfy `abs(left-right) <= 1e-12 * max(left,right)`, with no fixed absolute floor. This checks cyclic continuation of the supplied spans, rather than guessing a period or correcting the knots. Unknown counts, overlap disagreements, repeated/decreasing knots and incompatible exterior spans reject conversion/evaluation. Knot multiplicity and other compact native API conventions remain outside this bounded curve contract.

Positive finite weights whose smallest/largest normalization underflows to zero also reject. A periodic HATCH with rational flag zero and nonunit stored weights has no qualified conversion interpretation and rejects conversion. The source packet remains available for storage, cloning and direct affine transformation. The returned standalone entity uses its existing rational-flag export convention; this module does not claim to preserve a HATCH's rational bit through a distinct standalone entity type. Existing storage admission is unchanged, including previously accepted periodic packets whose shapes this API cannot evaluate.

Periodic `PolygonalVertexes` now chooses the supplied active domain before the separate closed-control-polygon condition. Coincident first/last compact controls no longer cause sampling over exterior knot padding. The periodic evaluator scales a temporary weight array by its largest weight, leaving the exposed stored weights unchanged. A nonpositive/nonfinite denominator or nonfinite result rejects instead of producing an artificial point at the origin. A requested parameter grid that underflows or rounds adjacent parameters together also rejects; it does not return repeated samples as though they resolved the requested grid. The numerical changes are confined to periodic evaluation; the nonperiodic evaluator retains its prior behavior. The sample count excludes the duplicate periodic endpoint, preserving the API's existing convention. This is sampled parameter evaluation, not a new adaptive tessellation or error-bound API.

Independent producer evidence uses ezdxf 1.4.4 public [closed uniform B-spline and BSpline APIs](https://ezdxf.readthedocs.io/en/stable/math/core.html) and its public HATCH writer. Twelve pinned drawings cover six DXF versions and both transports, with 144 expanded periodic packets: degrees 1/2/3, unit/nonunit positive weights, uniform and shifted nonuniform dyadic knots. The manifest retains the public evaluator's actual parameter mapping: for a negative-start input, that implementation normalizes its knots affinely, so independent sample parameters account for both the observed scale and shift. netDxf's stored knot values are never normalized. The [B-spline basis properties](https://pages.mtu.edu/~shene/COURSES/cs3621/NOTES/spline/bspline-property.html) give the ordinary expanded knot/control relation and local support underlying the active-domain comparison. No third-party implementation is copied.

Legacy compact HATCH packets are compatibility storage evidence, not valid expanded DXF curve packets: ezdxf's HATCH audit rejects that compact count relation. Tests intentionally preserve those original HATCH arrays and separately export their converted canonical standalone curves into valid drawings. The verifier audits the canonical outputs, compares the compatibility packets without claiming native validity, and never repairs or silently replaces the original HATCH. Canonical expanded HATCH drawings are audited directly. Unsupported conversion forms also have explicit storage/clone/identity-transform/reload checks, without a shape or native-acceptance claim.

Qualification covers direct adapters, actual standalone writer packets, repeated text/binary reloads, OCS/world controls and fit/tangent metadata, independent BSpline comparisons against emitted netDxf samples, degree 1–10, coincident compact endpoints, common weight scaling from the smallest positive binary64 value through large finite weights, and all-or-nothing unsupported-input boundary creation. The initial frozen preceding DLL rejects all twelve fresh producer conversion observations, and a failed `CreateBoundary(true)` changes a formerly nonassociative HATCH to associative. The same final 222-case test binary records 53 passes / 169 failures against that frozen preceding DLL and 222 passes / zero failures against the final module DLL. The two unrepresentable sampling-grid probes preserve their actual baseline outputs: a request for 64 points produced only one distinct point with subnormal knots and five distinct points with a large knot offset; the final evaluator refuses both requests before returning a misleading grid.

Debug and Release each pass 9,483 HATCH cases (including 222 new cases) and 1,556 standalone SPLINE cases. All 24 HATCH and five SPLINE artifact gates pass in each configuration. The periodic gate verifies 96 case drawings, 1,152 converted curves and 73,728 actual evaluator samples, with maximum world-space error 9.68e-15 and five rejected actual-output corruptions. It audits 96 canonical drawings with zero errors or repairs, preserving the separate compact-storage boundary described above.

An unchanged independent review uses homogeneous de Boor evaluation over the original producer control/weight/knot arrays and a separately implemented OCS basis. Its final replay compares the same 96 case drawings / 1,152 curves / 73,728 emitted samples through 169,344 point comparisons, with maximum absolute error 4.45e-15 and zero audit errors or repairs in the 96 canonical drawings. This final replay supersedes its provisional run; the corpus counts are not additive. All five Release target frameworks and Debug net8.0/netstandard2.0 build with zero errors and the existing 561 CS1591 warnings per target; there are no additional warning categories.

A separate source-boundary review also passes 12 independent cases against each frozen Debug/Release DLL. These cover late conversion/world-coordinate failures before association changes, projected tangent overflow, and a tiny valid active domain with a relatively invalid exterior span. The original membership, paths, source occurrences/reactors, arrays, seeds and callback counts remain unchanged on the tested refusals. These probe cases are separate from the 222 registered regression cases and the geometry corpus.
