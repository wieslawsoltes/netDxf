# IMAGE affine pixel geometry and absolute rotation

IMAGE stores a WCS insertion point and two independent WCS per-pixel vectors.
The typed model stores the two directions in a plane coordinate system, with
separate drawing width and height. Transforming the old normal as an ordinary
direction and dropping the resulting Z components can distort this basis.

The image transform now derives its destination plane through the existing
PlanarEntityTransform helper, then maps each original axis into that plane.
The insertion point uses the existing exact affine-point helper. Axis lengths
are measured with scaled components, without a reciprocal of a subnormal value.
The axes are transformed separately from the insertion point: a large translation
does not erase image dimensions through subtraction of rounded world corners.
Reflected and skewed independent pixel bases remain representable.

Every input/result is prepared before publication. Nonfinite, projective,
collapsed or numerically collinear input rejects rather than substituting a
positive epsilon dimension. The existing planar helper's 1e-14 rank policy is
retained, and the same threshold applies to the image's relative U/V directions.
This is a deliberate restriction on degenerate transforms, not universal exact
arithmetic or a promise that every finite mathematical map is representable.
Intermediate basis operations can still overflow before a scaled final result
would be representable. No such failure is silently converted to geometry.

Identity preserves stored geometry and graphics. Translation retains the plane,
axis and dimension fields. Genuine affine changes clear stale common proxy
bytes. Matrix4 validation happens before dispatch to the virtual Matrix3 entry;
valid matrices retain that dispatch. The implementation uses base Normal while
preparing/publishing to avoid subclass property callbacks interrupting the edit.
This is entity-local staging, not transaction-wide rollback or callback isolation.

## Rotation and direct edits

Rotation is now an absolute U-axis angle in degrees, not a delta added to the
previous angle. V rotates by the difference, retaining relative skew and
handedness. U is stored from the requested normalized angle; repeated equivalent
assignments and assigning the getter back preserve the state and cache.
Nonfinite requested angles reject before mutation. Width, height, position,
normal, clipping coordinates and image definition are not rotated or rescaled
by this angle property itself.

Position, Width, Height, Uvector and Vvector assignments invalidate graphics only
when stored coordinates change. Their pre-existing input admission and public
normalization behavior are retained. Rotation/affine preparation validates its
source before editing it. Rendering-appearance setters, definition replacement,
clipping-boundary replacement and deep mutations are not newly observed here.
Callers remain responsible for stale caches caused by those other operations.
No proxy graphic is generated by this increment.

## Verification design

The conformance registration adds API matrices for both affine entry points,
three planes, ordinary and reflected-skew pixel bases, tiny/large uniform scales,
source ownership, cloning, invalid matrix components, projective input, singular
maps, overflow, virtual callbacks, repeated absolute angles and direct-edit cache
states. The wire corpus uses all six typed profiles, both input/output transports,
modelspace, paperspace and referenced/unreferenced blocks. Each drawing contains
48 images, including repeated absolute-angle assignments, plus following geometry.
The image file is a metadata-only reference; no raster file or pixel decoder is
used. Existing assertions/registrations are retained.

The independent checker reconstructs expected WCS insertion and pixel vectors
from fixed input axes and matrices. It checks physical tags and ezdxf objects,
references, graph integrity and common proxy packets. Mutations of actual output
records and missing/extra corpus controls must reject. Its bounded wire comparison
uses a documented 2e-12 relative scale with a unit floor; the C# tiny-scale API
checks instead scale their bounds to each expected vector. Pixel clipping
coordinates are checked in the typed round trips; this is not a new independent
qualification of every clipping-coordinate dialect.

The checker uses the existing byte-preserving tag loader, before generic scalar
casting can stringify binary chunks. It checks the exact ordered proxy packet,
including chunk boundaries and the expected 92/160 length code for each profile.
Changed, removed, duplicated and wrong-code packet fields must reject; both
legacy and modern stale-proxy insertions must reject. The independent image-size
assertion includes ezdxf's zero Z component for this declared two-dimensional value.

The shared installed-package consumer also exercises absolute/repeated rotation,
projective refusal, out-of-plane shear, cache retention through save/load, and
cache invalidation on a subsequent size edit. These assertions run with the
existing package consumer and the eight exact-asset runtime profiles.

The verifier is discovered by the existing core workflow. Exactly ci-build.yml
and release.yml remain; no additional workflow or publication permission is added.
Executed results belong in the PR, not inferred from this test design. Initial
authoring used repository tools while local execution was unavailable. A later
local environment recovered the exact source tree from the CI package archive
and ran the focused conformance suite and independent checker. Hosted validation
of the final source remains required before merge.
