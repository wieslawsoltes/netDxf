# Atomic affine transformation of stored SPLINE geometry

This task starts from the merged C# spline/HATCH stack at
`8874b7fccf77f7eb01b879be9939ca677f94cd38`, source tree
`94c5d0bc303f0a6e9313a39d7281e70eed9bc80c`. It does not change the JavaScript port.

## Contract

`Spline.TransformBy(Matrix3, Vector3)` now prepares controls, fit points,
optional start/end tangents and the inherited auxiliary normal before changing
any source field. Tangents keep their transformed magnitude and use the linear
map only. Null tangents stay absent and zero/collapsed tangents remain valid.
Both Matrix3 and Matrix4 paths reject nonfinite inputs and unrepresentable
results without publishing a partial transform. Matrix4 requires an exact
`(0, 0, 0, 1)` bottom row; projective terms are not silently discarded.

The implementation reuses `VertexAffineTransform` and the existing bounded
exact dyadic dot products. Point coordinates and tangent components are rounded
once to binary64, preserving finite cancellations even when intermediate
floating-point products would overflow. Nonzero final components that round to
zero reject under the existing helper's conservative admission policy. Exact
zero cancellation is allowed. This policy is not claimed to be AutoCAD's policy.

The inherited Normal remains auxiliary model state, not an inferred geometric
plane normal. Its existing vector-transform convention and collapsed-image
fallback are retained. It is checked for finite unit components independently
of a cached normalization flag. Normalization retains the existing helper's
floating-point accuracy; no universal correct-rounding claim is made.

All caller-visible point, knot and weight arrays retain their identities. Knots,
weights, fitting tolerances, creation method, periodic state, graph references,
appearance and XData are not rewritten. Exact identity and numerically unchanged
geometry preserve original vector bits and proxy graphics. The no-change check
treats signed zeros as equal; a changed transform need not retain lexical zero
signs. Changed geometry clears the common parent proxy, including tangent-only
changes. Publication does not invoke a derived Normal getter or setter.
Matrix4 still dispatches through the virtual Matrix3 method, preserving the
specialized HELIX similarity checks.

This is not a complete spline-admission validator: unchanged knot/weight
metadata and private associations are not validated or regenerated by a
geometry transform. The operation does not refit controls from fit points,
transform geometric XData, regenerate child proxies, or make concurrent caller
mutation safe. The prepared arrays and exact arithmetic have CPU/allocation
costs; no throughput improvement is asserted.

## Evidence and reproduction

The same 1,008 new cases pass 486 against the preserved baseline Release library
and 1,008 after this correction. The exact same Release test harness is used for
that comparison; no production stub or changed expected values are involved.
Focused Debug and Release runs both pass all 1,008 cases. Coverage includes
rational, fit-created and periodic splines; both transform APIs; four tangent
presence combinations; direct/nested storage; eight transformations; every
matrix/translation component with nonfinite values; late failures in each point
and tangent collection; exact cancellation; proxy handling; identity; and
throwing derived accessors.

`tools/verify_spline_affine_atomic.py` independently computes exact Fraction dot
products. It checks 432 source/after pairs (864 drawings), including 4,608 WCS
control/fit/tangent vectors, and rejects 89,208 actual ordered-packet changes,
omissions and duplications through the same comparator. Every selected SPLINE
tag is compared, including identity values and the proxy-retention policy.
Source controls or fit-point inputs are independently specified. Fit-created
control polygons are metamorphic input, not independently requalified fitting.
All drawings have zero ezdxf graph errors or repairs. The wire corpus uses the
six existing typed profiles R2000 through R2018, text and binary.

```sh
DXF_TEST_FILTER=spline-affine-atomic/ dotnet run --project tests/netDxf.Conformance -c Release
python tools/verify_spline_affine_atomic.py artifacts/conformance
```

Complete-suite and hosted results are recorded in the PR against their exact
source heads, separately from these focused results. The earlier interrupted
compressed upload was corrupt; none of its unverified bytes was applied. This
implementation was reconstructed and tested on the recovered current source.

## Primary reference and remaining scope

Autodesk's SPLINE schema identifies controls, fit points and optional tangents
as WCS quantities:
https://help.autodesk.com/cloudhelp/2018/ENU/AutoCAD-DXF/files/GUID-E1F884F8-AA90-4864-A215-3182D47A9C74.htm

This establishes the stored coordinate model, not the library's rounding,
exception or admission policy. Native AutoCAD open/AUDIT/save/reopen, visual and
font equivalence, historical typed dialects, dependency-complete imports,
private FIELD/TABLE regeneration and general version conversion remain
unqualified. This task does not establish full AutoCAD or all-version parity.
