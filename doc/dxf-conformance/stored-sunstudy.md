# Stored SUNSTUDY empty-date packets

`DxfStoredSunStudy` retains the complete immutable `AcDbSunStudy` payload of the qualified internal-version-0, empty-date packet in R2013 and R2018. The source name and description, output type number, subset fields, raw range values and repeated hour flags have read-only projections. `Payload` retains every remaining value and its order. The four source pointers in groups340–343 resolve to actual accepted source objects; they remain nullable when the stored handle is zero.

The [Autodesk SUNSTUDY reference](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-1C7C073F-4CFD-4939-97D9-7AB0C1E163A3.htm) describes the public fields and repeated codes. The stored output number is not assigned an inferred enum meaning. Repeated group290 values are exposed as raw boolean flags, not clock times. No solar, scheduling, date-list or rendering evaluation is performed.

Qualification uses the [six pinned IxMilia 0.8.4 producer carriers](../../tests/fixtures/sunstudy-producer/README.md). Four source files contain no selected dates and no hour entries; two ASCII sources contain four ordered hour flags. Each valid source packet is tested after explicit text and binary input conversion and saved in both output formats. These conversions establish netDxf transport behavior for the unchanged logical packet. They do not reclassify the producer's malformed binary-hour attempts as positive evidence. The six original whole files retain their ten invalid empty DIMSTYLE pointers, while the disclosed carriers change only those unrelated pointers to null0.

Unknown versions, earlier profiles, nonempty date arrays, additional fields and private subclasses remain complete opaque objects. The exact public empty-date signature rejects inconsistent hour counts and nonfinite spacing. No minimum native AutoCAD profile or nonempty-date interpretation is claimed.

A promoted object requires its exact accepted owner dictionary and registered source ancestry. The owner chain, source document, source profile and pointer identities remain fixed. Cloning, foreign adoption, erasure of the object or an owning subtree, and removal of exposed dependencies are guarded before mutation. Common extension dictionaries, persistent reactors and genuine XData retain the existing metadata APIs. Exposed standard pointers in opaque SUNSTUDY variants also participate in resource-removal guards; arbitrary320–329 fields remain uninterpreted.

`StoredSunStudyTests.cs` verifies complete source packets, transport sentinels, zero references, raw projections, metadata, unknown-shape preservation, missing references, owner failures, and lifecycle atomicity. `verify_stored_sunstudy.py` requires every typed and opaque output and checks complete study bodies, physical owner and pointer identities with actual parsed-field corruption controls. Its low-level validation does not claim high-level native CAD acceptance.
